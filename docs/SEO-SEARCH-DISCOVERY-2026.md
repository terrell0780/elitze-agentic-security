# ELITZE Search Discovery & Web Analytics — 2026

## Canonical public web identity

Primary public URL:

- https://elitze.ca/

Secondary hostname:

- https://www.elitze.ca/

The application permanently redirects the www hostname to the apex hostname so search engines receive one canonical site identity. The sitemap and robots output advertise https://elitze.ca.

Do not create separate duplicate content on the www hostname.

## Search-engine discovery implemented in the repository

The production branch contains:

- robots.txt generated by Next.js with an absolute sitemap URL.
- sitemap.xml generated by Next.js with canonical public application routes only.
- www.elitze.ca → elitze.ca permanent host redirect.
- Organization and WebSite JSON-LD.
- Search-friendly title, description, language, Open Graph and crawler directives.
- Verification-tag support for Google, Bing, Yandex and Baidu through deployment environment variables.
- public/llms.txt for machine-readable product context.
- Authenticated/console endpoints excluded from the public sitemap and crawler directives.
- Analytics blocked until optional analytics consent is granted.

Search engines may still choose different snippets, titles, canonical URLs or indexing decisions. Repository changes cannot guarantee ranking or indexing.

## Required webmaster verification

The site owner should verify both hostnames in Google Search Console:

1. Add a Domain property for elitze.ca when possible.
2. Also verify the URL-prefix properties for https://elitze.ca/ and https://www.elitze.ca/ so both hostnames are visible during migration/canonical consolidation.
3. Submit:
   - https://elitze.ca/sitemap.xml
4. Use URL Inspection on:
   - https://elitze.ca/
   - https://elitze.ca/platform
   - https://elitze.ca/security
   - https://elitze.ca/use-cases
   - https://elitze.ca/about
   - https://elitze.ca/faq
   - https://elitze.ca/sales

Google documents that sitemap submission and individual indexing requests are discovery signals, not guarantees of inclusion.

## Bing / Copilot

Add https://elitze.ca/ to Bing Webmaster Tools and verify ownership. Submit the same sitemap.

Where an IndexNow key is configured, use IndexNow for URL changes. Do not commit an IndexNow secret/key to Git unless the public key file and deployment mechanism are intentionally configured.

## Other search engines

The public site uses standards-based discovery rather than engine-specific tricks:

- crawlable HTML links
- XML sitemap
- robots.txt
- canonical host consolidation
- structured data
- descriptive metadata

This is the portable foundation used by additional crawlers and search systems. Engine-specific ownership verification values are supported but must be supplied by the site owner.

## Similarweb

Similarweb does not require an ELITZE-specific browser cookie to measure a site. Similarweb states that its behavioral dataset is built from multiple sources and that its anonymous behavioral data does not use cookies.

For owner-controlled first-party measurement, keep GA4 configured in the deployment environment. Similarweb supports private GA4 connection for website owners. That connection is made inside the Similarweb account; it is not a repository setting.

Recommended production environment variables:

- NEXT_PUBLIC_GA4_MEASUREMENT_ID=<real GA4 ID>
- NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION=<real Google verification value>
- NEXT_PUBLIC_BING_SITE_VERIFICATION=<real Bing verification value>

Do not insert placeholder IDs into production.

## Cookie behavior implemented

The site now uses a first-party consent preference:

__Host-ELITZE_CONSENT

Values:

- necessary — optional analytics blocked.
- analytics — optional analytics may load when GA4/Ads IDs are configured.

Properties in HTTPS production:

- Secure
- HttpOnly is intentionally not used because the browser-side preference UI must read/write the visitor's choice.
- SameSite=Lax
- Path=/
- Max-Age=15552000 (180 days)
- __Host- prefix prevents a Domain attribute from being used and requires HTTPS + root Path.

Optional analytics scripts are not loaded before consent. When consent is withdrawn, known Google Analytics/Ads first-party cookies are cleared and Google Consent Mode storage settings are updated to denied where the measurement runtime is present.

The consent UI provides a persistent Cookie settings control and links to the Privacy & Cookies page.

## Legal/operational note

The implementation is a technical consent mechanism, not a legal determination of which privacy regime applies to a visitor. Privacy notices, consent requirements and analytics disclosures should remain aligned with the jurisdictions and customer contracts that apply to the deployed service.

## Verification checklist after deployment

Confirm these URLs return successfully:

- https://elitze.ca/
- https://www.elitze.ca/ → permanent redirect to https://elitze.ca/
- https://elitze.ca/robots.txt
- https://elitze.ca/sitemap.xml
- https://elitze.ca/privacy

Then check:

- page source contains Organization and WebSite JSON-LD
- no GA4/Google Ads script is present before analytics consent
- analytics script appears only after analytics consent
- consent cookie is Secure; SameSite=Lax; Path=/ on HTTPS
- www does not remain as a duplicate canonical public host
- Search Console reports the sitemap as processed
- Bing Webmaster Tools reports the sitemap as processed
- Similarweb shows the domain and, when connected, the private GA4 data source
